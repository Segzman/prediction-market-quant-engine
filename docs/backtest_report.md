_Generated by `research/backtest_report.py`. Do not edit by hand; rerun the script._

## Sample and split

- Source logs: `trades_both.jsonl`, `trades_conviction.jsonl` (two runs over overlapping 5-minute windows, kept as separate sources).
- Windows in sources: 180; excluded (last observation more than 30 s before close): 50.
- Sample rows: 905 (1 in 16 ticks plus every would-trade tick; chronological order; anonymized).
- Chronological split by window end: train 45 windows / 649 states; **test 20 windows / 256 states**.
- Test states with a directional call (strongest side UP or DOWN): 216.
- Test-set decisions (first would-trade tick per source and window): 28.

**Sample size is small.** The test set covers a few dozen windows. Ticks inside one window are strongly correlated, so the effective sample is closer to the number of windows than the number of states. Confidence intervals below are therefore wide, and no result here establishes an edge.

**Outcome labels are a proxy.** The logs contain no settlement result for most windows (resolution records are early exits with `resolved_up = null`). UP is defined as last observed BTC price above the window open price, which is close to but not identical to the contract settlement rule. PnL below is therefore a settlement-style estimate on that proxy, not realized PnL. Recorded early-exit PnL is not used.

**What JEV measures.** JEV answers whether observed BTC movement corroborates the strongest Polymarket side (directional agreement), not the settlement probability. Its probability is mapped to P(Up) as `p` when the side is UP and `1 - p` when DOWN. This mapping is an assumption, so JEV's Brier and log loss are not directly comparable to the models as settlement forecasts. Sample size on the covered subset is small.

## Method notes

- Models A, B, C, P are the probabilities logged by the bot; nothing is refit here. In the source logs B and C are identical on every row (8,125 of 8,125 in `trades_both.jsonl`), so the report cannot separate them; the cause (for example Model C falling back to B, or a logging duplicate) is not visible in these files.
- Logged probabilities are used as-is. The chronological split is used only to choose which states are scored. Model C's calibration artifact may have been fit on overlapping history, so train-period scores are not reported.
- Tick and momentum features for JEV are reconstructed from logged candidate ticks (about 2.5 s cadence, 12 s tick lookback, 30 s Polymarket lookback) and are approximations of the production sub-second feed.
- Brier, log loss, ECE and reliability are computed on P(Up) with 10 equal-width bins.
- Wilson intervals use z = 1.96. Trade bootstrap uses 2000 resamples of windows with a fixed seed.
